# コードレビュー

確認済みの[文脈](../context-discovery/SKILL.md)を使い、[レビュー規約](../../../docs/policy/review.md)を読む。比較元・対象の版と依頼された範囲を確認し、Git差分に加えて変更を理解するための周辺本文・呼び出し元を読む。

Reviewabilityから始め、変更内容に該当する後続段階を規約の順序で評価する。先行段階の未解決事項に依存する範囲を保留し、既に明らかな問題は併せて示す。各段階の評価基準はレビュー規約を参照する。

設計・実装・必要なテストを周辺コードと照合する。[テスト方針](../../../docs/policy/testing.md)から既存検証の保証範囲を確認する。文書の変更が含まれる場合は[documentation-review](../documentation-review/SKILL.md)も利用する。

適用した段階ごとに、パス・位置・根拠・影響と規約のラベルを付けて指摘する。評価不能な範囲はレビューの制約として分ける。質問や指摘を必ず作る必要はない。レビューの依頼だけで実装・保護文書の変更まで行わない。
